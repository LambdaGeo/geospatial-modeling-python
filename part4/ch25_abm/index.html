    Chapter 24's cellular automata all shared one constraint: a fixed grid, one rule applied identically to every cell, cells that neither move nor disappear. Real agents don't cooperate with that constraint — they walk, they compete for space, they're born and they die mid-run. This chapter is where DisSModel stops treating every spatial actor as a stationary cell.

    Agents, Societies and a Cellular Space¶

    dissmodel-abm follows TerraME's own vocabulary. An agent type is a Python class: its class attributes are the default state of every new agent, init() runs once when an agent is created, and execute() runs once per step. A Society holds the agents of one type. A CellSpace is the grid they live on, and placement puts each agent in a cell.

    Three things are adapted to Python and to the rest of DisSModel:

    • One clock. A model is an ordinary DisSModel Model (Chapter 22), run by Environment. There is no Timer or Event: the model's execute() says what happens in a step.
    • One random generator. AgentModel(seed=...) creates a NumPy generator that every society, cell space and agent uses (self.rng, agent.rng). The same seed gives the same run, byte for byte. Never draw from numpy.random or random inside a model: those draws escape the seed.
    • Cells are raster bands. A cell's attributes are the bands of a RasterBackend (Chapters 24 and 28), so agents read and write one cell at a time (cell.state = SOIL), while a rule that applies to every cell can update a whole band with NumPy, or run as a dissmodel-ca cellular automaton on the same backend. RasterMap draws the bands.

    The smallest complete model: walkers that move to an empty neighbor at every step and die with probability 0.01.

    Copied! 
    from dissmodel_abm import Agent, AgentModel, CellSpace, Society


class Walker(Agent):
    age = 0                           # default state of every new agent

    def execute(self):                # once per step
        self.walk_to_empty()
        self.age += 1
        if self.rng.random() < 0.01:  # the model's generator
            self.die()


class Walkers(AgentModel):
    def setup(self, dim=20, quantity=50):
        self.cs = CellSpace.grid(dim)
        self.cs.create_neighborhood()                     # Moore, as in TerraME
        self.society = Society(Walker, quantity=quantity)
        self.place(self.society, cellspace=self.cs)       # random, one per cell

    def execute(self):
        self.society.execute()


env = Environment(start_time=1, end_time=100)   # 100 steps, as TerraME's finalTime = 100
model = Walkers(seed=42)
env.run()
print("Agents alive after 100 steps:", len(model.society))
print("Agents counted in the n_agents band:", int(model.cs.backend.arrays["n_agents"].sum()))

    The dissmodel-abm Package¶

    Like the other extension packages since Chapter 21, dissmodel-abm is not on PyPI; install the tagged release from GitHub:

    pip install "git+https://github.com/DisSModel/dissmodel-abm.git@v0.2.0"

    Six of the twelve models of TerraME's logo package (version 0.5.6) ship in dissmodel_abm.models, written to follow the Lua code rule by rule, with the original defaults:

    dissmodel_abm.models TerraME logo (lua/) What it exercises
    SingleAgent SingleAgent.lua walkToEmpty
    Schelling Schelling.lua Group, Trajectory, wrapped neighborhood, one move per step
    PredatorPrey PredatorPrey.lua two societies, reproduce, die, a cell rule (pasture regrowth)
    LifeCycle LifeCycle.lua births and deaths by age, agents sharing a cell
    Ants Ants.lua void placement, enter, bands written by agents, evaporation
    Disease Disease.lua a social network redrawn every step, messages with delay; no space

    The other six — GrowingSociety, Heatbugs, Labyrinth, Overpopulation, SpatialPD and Sugarscape — have no port yet.

    This chapter works through three in depth: PredatorPrey, which rebuilds Chapter 23's Lotka-Volterra system from individuals; Schelling, whose port hid a subtle difference from TerraME; and Disease, which uses social networks and messages instead of space.

    Theory: Bottom-Up Modeling¶

    Agent-based modeling appears under several names across the literature — ABM, multi-agent systems, individual-based modeling — spanning economics, sociology, ecology, and political science. What unifies them is a bottom-up approach: complex system behavior emerges from the interaction of discrete agents, rather than being specified as an aggregate equation the way Chapter 23's system dynamics models are. An agent is any actor able to affect itself, its environment, and other agents.

    Helen Couclelis's classification of ABM applications, along two axes — natural versus artificial agent, natural versus artificial environment — places most of the models in this book in the same quadrant:

    Natural environment Artificial environment
    Natural agent Behavioral experiments Descriptive model
    Artificial agent Engineering applications e-science

    PredatorPrey, coming up next, sits in "descriptive model": its agents are meant to stand for real animals (natural agents, in this classification), placed in a deliberately simplified, artificial environment.

    Nigel Gilbert's case for why ABM is worth its extra complexity, relative to Chapter 23's aggregate models, comes down to three things a bottom-up model represents directly instead of assuming: structure (it emerges from agent interaction rather than being imposed from outside), agency (agents have goals and beliefs that drive their actions), and dynamics (agents move, learn, and change position — spatially and socially — over the course of a run). ABM also handles qualitative and relational data that System Dynamics' continuous aggregate quantities simply can't represent — who is a given type, who is adjacent to whom.

    Case Study: Predator-Prey, From Equation to Individual¶

    Chapter 23 modeled predator and prey as two continuous stocks under Lotka-Volterra. TerraME's logo/PredatorPrey.lua rebuilds the same phenomenon bottom-up, with rabbits, wolves and a pasture that regrows, all sharing one cellular space. Each ODE term becomes an individual rule:

    ODE term Agent rule in PredatorPrey.lua
    prey growth a rabbit eats the pasture of its cell (+20 energy) and, with 30 or more, gives birth in an empty neighbor, splitting its energy with the child
    predation a wolf that finds a rabbit in a neighboring cell eats it, gaining 20% of the rabbit's energy
    predator growth a wolf with 50 or more energy gives birth in an empty neighbor, halving its energy
    mortality every agent loses energy each step (rabbits 1, wolves 4) and dies below zero
    resource limit eaten pasture becomes soil and grows back on its fourth step 
    -- PredatorPrey.lua (TerraME logo) -- rabbit agent shown
model.rabbit = Agent{
	energy = 40,
	name = "rabbit",
	eat = function(self)
		if self:getCell().state == "pasture" then
			self:getCell().state = "soil"
			self.energy = self.energy + 20
		end
	end,
	execute = function(self)
		local cell = self:getCell():getNeighborhood():sample()
		if cell:isEmpty() then self:move(cell) end

		self.energy = self.energy - 1
		self:eat()

		cell = self:getCell():getNeighborhood():sample()
		if self.energy >= 30 and cell:isEmpty() then
			local child = self:reproduce()
			child:move(cell)
			self.energy = self.energy / 2
			child.energy = self.energy
		end

		if self.energy < 0 then self:die() end
	end
}

    The rabbit in dissmodel_abm.models.predator_prey is the same rule, line for line:

    class Rabbit(Agent):
    energy: float = 40
    name = "rabbit"

    def eat(self):
        cell = self.cell
        if cell.state == PASTURE:
            cell.state = SOIL
            self.energy += 20

    def execute(self):
        cell = self.cell.neighborhood.sample()
        if cell.is_empty():
            self.move(cell)

        self.energy -= 1
        self.eat()

        cell = self.cell.neighborhood.sample()
        if self.energy >= 30 and cell.is_empty():
            child = self.reproduce()
            child.move(cell)
            self.energy /= 2
            child.energy = self.energy

        if self.energy < 0:
            self.die()

    The pasture is a cell rule, the same for every cell, so the model writes it with NumPy over the whole band instead of a loop over cells — the same choice Chapter 24's raster automata make:

    def regrow(self):
    state = self.cs.backend.arrays["state"]
    count = self.cs.backend.arrays["count"]
    soil = state == SOIL
    count[soil] += 1
    back = soil & (count == 4)
    state[back] = PASTURE
    count[back] = 0

def execute(self):
    self.regrow()                  # cells first, as in the original Timer
    self.rabbit_society.execute()
    self.wolf_society.execute()

    The rabbits fill most of the 900 cells within about 15 steps, limited by space and pasture rather than by the wolves; the wolves then grow on the abundant prey, eat the rabbits down, starve back, and the two populations oscillate. The phase plane does not close into Chapter 23's neat loop: the cycles are noisy, because they are made of individual births and deaths. Run it with other seeds and the oscillation keeps its shape while the details change — which is exactly why an agent-based port has to be compared with its original by distribution, as the last section of this chapter does.

    Schelling: When a Port Looks Right and Isn't¶

    Schelling's segregation model places agents of two kinds on a grid; an agent is unhappy when fewer than preference of its neighbors are of its own kind, and at each step one unhappy agent moves to a random empty cell. TerraME's version keeps the unhappy agents in a Group:

    -- Schelling.lua (TerraME logo), the step
step = function()
	model.unhappy_agents:filter()               -- a Group of unhappy agents

	if #model.unhappy_agents > 0 then
		local myagent = model.unhappy_agents:sample()
		local empty_cells = Trajectory{
			target = model.cs,
			select = function(cell) return cell:state() == "free" end
		}
		myagent:move(empty_cells:sample())
	end
end

    and the port in dissmodel_abm.models.schelling:

    def setup(self, dim=25, free_space=0.05, preference=3):
    ...
    self.unhappy_agents = Group(self.society, select=lambda a: a.is_unhappy(self.preference))

def execute(self):
    self.unhappy_agents.filter()
    if len(self.unhappy_agents) > 0:
        agent = self.unhappy_agents.sample()
        agent.move(self.cs.sample_empty())

    The two read the same. The subtlety is in what filter() means. A first version of the port rebuilt the group from the whole society at every filter(), which is what most readers expect. TerraME's Group:filter does something narrower: it applies select again to the current members only; rebuilding from the society is a different method, rebuild(). So in TerraME an agent that became happy leaves the group for good — even if a later move makes it unhappy again — and the group empties while some agents are still unhappy. The next cell shows the two methods side by side:

    Social Networks and Messages: Disease¶

    Not every agent-based model needs space. TerraME's logo/Disease.lua spreads an infection through contacts: every infected agent sends a message to six agents drawn at random, each message infects a susceptible receiver with probability 0.25, and the network is drawn again at every step. In dissmodel-abm the network is created with create_social_network and the messages go through message and on_message:

    class Person(Agent):
    state = "susceptible"
    counter = 0

    def on_message(self, msg):                       # TerraME on_message
        if self.state == "susceptible" and self.rng.random() < self.model.probability:
            self.sick()

    def execute(self):
        if self.state == "infected":
            for other in self.connections():         # forEachConnection
                self.message(other, delay=1)         # arrives at the start of the next step
            ...

    with society.create_social_network(quantity=contacts, inmemory=False) in setup(): inmemory=False makes the network a function, so every call to connections() draws new contacts, as TerraME does. A message sent with delay=1 waits in the sender's society and is delivered by society.execute() at the start of the next step, before the agents act.

    Checking a Port When the Random Numbers Differ¶

    Chapter 23's system dynamics models can be compared with TerraME value by value, and Chapter 24's deterministic automata cell by cell. An agent-based model draws random numbers at every step, and Lua and NumPy draw different ones, so a single run of the port and a single run of the original are not expected to agree. What should agree is the distribution: run both many times and compare.

    The terrame-goldens repository holds what TerraME 2.0.1 computed running the logo models for seeds 1 to 50, and dissmodel-abm's test suite compares 20 runs of each port with them, at a few steps, with a two-sample Kolmogorov–Smirnov test and a test on the means:

    Model Variable, step TerraME (50 seeds) Port (20 seeds)
    Schelling unhappy agents (%), t = 500 5.6 ± 0.8 5.6 ± 1.0
    PredatorPrey rabbits, t = 20 855 ± 6 859 ± 7
    LifeCycle agents, t = 40 101 ± 16 92 ± 12
    Ants food left, t = 40 90.6 ± 3.1 90.3 ± 4.0
    Disease never infected, t = 30 2.7 ± 1.8 2.6 ± 1.2

    Three lessons came out of this comparison, and each is worth keeping beyond this package:

    • One run of the original is not a reference. Before the goldens existed, the ports were compared with the single reference charts kept in logo's own tests. Ants and Disease seemed to differ (97 food left instead of 90; 12 to 17 agents never infected instead of 2). Over 50 TerraME runs, both differences disappeared: the chart was one draw among many.
    • A distribution test finds what a plausible-looking run hides. The Schelling difference above was found this way, not by reading the code.
    • When a model has an exact answer, use it. LifeCycle is a branching process whose mean population can be computed exactly (97.8 agents at t = 40). The 50 TerraME runs lie above it and the 20 runs of the port below it, both by chance; with 2,000 runs the port gives 98.1, and the package tests check it against the exact value.

    What's Not There Yet¶

    The package states its own limits (docs/agent.md):

    • A vector space. The cellular space is raster only; a space of polygons from a GeoDataFrame, with the neighborhoods of dissmodel.geo.vector, is planned behind the same interface.
    • Several named placements, and neighborhoods other than Moore and von Neumann (TerraME's mxn, function and coord strategies).
    • State machines (State, Jump, Flow).
    • Six logo models without a port, listed above.

    Chapter 34's migration guide checks a TerraME model against this list before porting it.

    Summary¶

    Key concepts introduced¶

    • An agent type as a Python class (init(), execute(), class attributes as default state), a Society of agents, a raster CellSpace whose cell attributes are the bands of a RasterBackend, and TerraME's placement strategies
    • Three adaptations to DisSModel: Environment as the only clock, one seeded generator per model, and cells as raster bands that agents write one at a time and cell rules update with NumPy
    • The TerraME-to-dissmodel-abm concept mapping, name for name
    • PredatorPrey as Chapter 23's Lotka-Volterra rebuilt from individuals; Schelling and the difference between Group.filter() and Group.rebuild(); Disease with social networks and delayed messages
    • Comparing an agent-based port with its original by distribution, over many runs, and why one reference run is not enough
    • What dissmodel-abm does not do yet — vector space, several placements, state machines, six logo models — which Chapter 34's migration guide checks against

    Chapter 26 leaves the general-purpose paradigm chapters behind and turns to a specific domain: land use and cover change, built on the same Model foundation this Part has spent five chapters establishing.
